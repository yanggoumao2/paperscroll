# How it works

## Pipeline

Runs on start (if the last sync is older than 12 h or categories changed) and at the configured `sync_times`.

1. **Ingest** (`server/paperscroll/arxiv.py`) — queries the arXiv API per category in 7-day slices, 1,000 results
   per page with ≥3 s between requests. New categories are backfilled over the whole window; existing ones are
   updated from three days before the newest paper. A newer version of a paper replaces the old record and is
   re-embedded if its text changed.
2. **Embed** (`embed.py`) — [fastembed](https://github.com/qdrant/fastembed) runs
   `paraphrase-multilingual-MiniLM-L12-v2` (384-d, ONNX, CPU) on *title + abstract*. Vectors are stored in SQLite
   and kept in memory as a normalised matrix (~75 MB for 50k papers).
3. **Prune** — drops papers older than the window, except liked, saved or noted ones.
4. **Enrich** — `openalex.py` looks papers up by their arXiv DOI (`10.48550/arXiv.<id>`, 50 per request) for citation
   counts and the published venue; merged works are matched through their locations. `enrich.py` optionally adds
   Semantic Scholar TL;DRs. Both back off on rate limits and resume on the next run.
5. **Figures** (`figures.py`) — on demand, the first `figure` of the arXiv HTML version (and the authors'
   affiliations) is fetched, resized to ≤1280 px and cached. About 5% of papers have no HTML version and therefore
   no figure.

## Ranking (`rank.py`)

```
profile  q = topic + 0.7 · mean(liked, saved, noted) − 0.35 · mean(hidden)      (Rocchio, then normalised)
score      = z(cosine(q, paper))                      semantic similarity, standardised over candidates
           + w_fit · BM25(keywords, title + abstract)   SQLite FTS5
           + recency bonus                             exp(−age / 4 d) or exp(−age / 21 d)
           + quality bonus                             accepted venue (CCF-A / CORE A* weighs 1.5×) or log(1 + citations)
           + novelty · Gumbel noise                    sampling instead of a fixed order
```

Papers already shown or hidden are excluded. Each batch of six interleaves 0–3 *adjacent-field* cards drawn
from papers with a moderate similarity (z between 0.8 and 1.8). Every card carries its similarity percentile
and the keywords it mentions, shown as *为何推荐 (why recommended)*.

Dwell time is recorded (`view` ≥ 1.5 s, otherwise `skip`) for future use; likes, saves, notes and hides update the
profile immediately.

## At a glance (`glance.py`)

No language model is involved, so nothing is paraphrased or invented. The abstract is split into sentences
(abbreviation-aware, LaTeX cleaned) and three are selected with weighted cue patterns:

- **method** — "we propose / introduce / present …", "this paper presents …", "called X", …
- **problem** — among the sentences *before* the method: "however", "remains challenging", "limited", "fail", …
- **result** — among the sentences *after* the method: "outperforms", "state-of-the-art", numbers with `%` or `×`,
  "experiments show …"; availability statements ("code will be released") are skipped.

It also extracts the method name (title prefix or "called X"), the paper type, code/project URLs and page/figure
counts from the arXiv comment. On a random sample most cards get the right three sentences; when a pattern
misfires, the *close reading* sheet still shows the full abstract.

## Venue level (`tiers.py`)

`server/paperscroll/venue_tiers.json` is generated by `server/tools/build_tiers.py` from the CCF recommended
list (via the CCFrank4dblp data files) and the CORE/ICORE conference export. Short labels from the arXiv
comment ("Accepted to CoRL 2026") and long OpenAlex source names are normalised to an acronym first. Venues
missing from both lists (e.g. CoRL, RSS, RA-L, TMLR) show no level rather than a guess; *Findings* tracks are
labelled separately.

## Interface (`web/`)

Plain HTML, CSS and JavaScript without a build step. Layout of a card is computed on the device (`fitCard` in
`app.js`): the figure spans the full width at its natural height up to 40% of the card (taller figures are cropped
from the top), the three paragraphs receive the remaining lines in the order method → result → problem, and
less important elements step aside only when even two lines each do not fit. Layout is never changed while
the feed is scrolling, because that makes scroll-snap jump back. English text is hyphenated with TeX patterns
(`web/vendor/hyphen*`), since Android WebView cannot hyphenate on its own.

## HTTP API

| Method | Path | |
|---|---|---|
| GET | `/api/status` | library size, sync state, enrichment progress |
| GET / PUT | `/api/profile` | topic, keywords, ranking knobs |
| PUT | `/api/config` | categories, window, API keys |
| POST | `/api/sync` | start a sync now |
| POST | `/api/feed` | next batch of cards `{n, pin}` |
| POST | `/api/event` | `like`, `unlike`, `save`, `unsave`, `hide`, `comment`, `view`, `skip` |
| POST | `/api/reset_seen` | forget shown papers |
| GET | `/api/paper/{id}` · `/api/img/{id}` | one card · its key figure |
| GET | `/api/library?kind=` | `like`, `save`, `note`, `hidden`, `all` |
| GET | `/api/export?kind=&fmt=` | `bibtex`, `md`, `csv`, `json` |
